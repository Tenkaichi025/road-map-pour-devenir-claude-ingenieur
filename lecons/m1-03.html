Leçon 1.3

CSS et responsive

L'idée

Le CSS est une liste de règles : « ces éléments-là, avec ce style-là ». Chaque élément de la page est une boîte : le contenu, une marge intérieure (padding), une bordure (border) et une marge extérieure (margin). Pour placer ces boîtes, on utilise surtout Flexbox (aligner sur une ligne ou une colonne) et Grid (une grille).

Responsive veut dire : la même page s'adapte à toutes les largeurs d'écran. On écrit d'abord pour le téléphone, puis on ajoute des règles pour les écrans plus larges. Point important : l'IA ne voit jamais ta page sur un téléphone. C'est toi qui dois le vérifier.

Exemple concret

La page d'un événement : une soirée de développeurs au Plateau, avec une liste d'intervenants. Sur téléphone, une colonne. Sur ordinateur, trois. 

/* 1. Les couleurs sont définies une seule fois, dans des variables. */
:root {
  --accent: #0b6e4f;
  --texte: #1f1f1f;
}

h2 {
  color: var(--accent);        /* on réutilise la variable */
}

/* 2. Téléphone d'abord : une seule colonne. */
.intervenants {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1rem;
}

/* 3. À partir de 700 px de large, trois colonnes. */
@media (min-width: 700px) {
  .intervenants {
    grid-template-columns: repeat(3, 1fr);
  }
}

/* 4. Une image ne dépasse jamais de sa boîte. */
img {
  max-width: 100%;
  height: auto;
}

Et dans le HTML, une ligne indispensable :

<meta name="viewport" content="width=device-width, initial-scale=1">

Sans cette ligne, le téléphone fait semblant d'avoir un écran de 980 px de large. Il affiche alors la version ordinateur en tout petit. Avec elle, il utilise sa vraie largeur et les règles @media fonctionnent.

Quand deux règles se contredisent

C'est la cascade. La règle la plus précise gagne : un #id bat une .classe, qui bat une simple balise. À précision égale, c'est la dernière écrite qui gagne. Dans les outils du navigateur (panneau Styles), une règle battue apparaît barrée.

Vidéo

Vérifier le travail de l'IA

Avant d'accepter du CSS généré :

  • La balise <meta name="viewport"> est dans le <head>.
  • Teste dans le mode appareil (F12, puis Ctrl + Maj + M) à 375 px de large : aucune barre de défilement horizontale.
  • Pas de largeur fixe sur les grands blocs (width: 1200px). Préfère max-width.
  • Les images ont max-width: 100%.
  • Le texte est lisible sans zoomer (environ 16 px minimum). Les boutons sont assez grands pour un doigt (environ 44 px de haut).
  • Les couleurs répétées sont dans des variables (--accent), pas copiées 30 fois.
  • Peu ou pas de !important. Quand l'IA en met partout, c'est souvent qu'elle force un style au lieu de comprendre pourquoi il ne s'applique pas.

À retenir

  1. Une règle CSS = un sélecteur + des propriétés.
  2. Tout est une boîte : contenu, padding, bordure, margin.
  3. Flexbox pour aligner sur une ligne ou une colonne, Grid pour une grille.
  4. Responsive : on commence par le téléphone, puis on élargit avec @media.
  5. Vérifie toujours à 375 px. C'est là que l'IA se trompe le plus.

Exercice 1 · guidé

Changer tout le thème en deux lignes

  1. Ouvre exercices/m1-03/evenement/index.html dans le navigateur.
  2. Appuie sur F12, onglet Éléments (Elements). Clique sur la balise <h1> dans l'arbre. À droite, le panneau Styles montre toutes les règles qui s'appliquent au titre.
  3. Dans ce panneau, décoche la case devant font-size : le titre change. Recoche-la. Rien n'est enregistré, tu ne fais que tester.
  4. Clique sur <html> dans l'arbre. Dans la règle :root, clique sur la valeur de --accent et remplace-la par #c8462b. Observe toute la page.
  5. Maintenant, fais le changement pour de vrai : dans style.css, change --accent et --fond, enregistre, recharge.

Résultat attendu : en modifiant 2 lignes, tu changes la couleur du bandeau, des titres, de la date et du bouton.

Indices

Tu ne trouves pas :root ? Fais défiler le panneau Styles quand <html> est sélectionné.

Correction

Toutes les règles utilisent var(--accent) au lieu d'écrire la couleur. Changer la variable change donc tous les endroits d'un coup. C'est ce que tu dois exiger de l'IA : des variables pour les couleurs et les polices, pas des codes couleur copiés partout.

Exercice 2 · semi-guidé

Faire ajouter une grille, la tester à 3 largeurs

  1. Copie le dossier evenement dans un dossier de travail. Ouvre Claude Code dans cette copie et demande :
Dans index.html, ajoute une section « Intervenants » avant
« Infos pratiques », avec 6 intervenants (nom, sujet, et une
photo en carré de couleur à la place d'une vraie image).
Une colonne sur téléphone, deux à partir de 600 px, trois à
partir de 900 px. Utilise CSS Grid et les variables déjà
présentes dans style.css. Ne modifie rien d'autre.
  1. Ouvre le mode appareil (Ctrl + Maj + M) et teste à 375 px, 768 px et 1280 px.
  2. Passe la liste « Vérifier le travail de l'IA » sur le CSS ajouté.
  3. Si un point ne passe pas, demande une correction précise.

Résultat attendu : 1, 2 puis 3 colonnes selon la largeur, aucun défilement horizontal, et aucune nouvelle couleur écrite en dur dans le CSS.

Indices

Dans style.css, cherche # suivi de 3 ou 6 caractères : si l'IA a ajouté des codes couleur au lieu d'utiliser var(--accent), c'est un point à corriger.

Correction

Le CSS attendu ressemble à ceci :

.intervenants {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1rem;
}
@media (min-width: 600px) {
  .intervenants { grid-template-columns: repeat(2, 1fr); }
}
@media (min-width: 900px) {
  .intervenants { grid-template-columns: repeat(3, 1fr); }
}
.intervenant .photo {
  aspect-ratio: 1;
  background: var(--accent);
}

Signaux d'alerte : des largeurs en px sur les cartes (width: 300px), une media query qui part de l'ordinateur (max-width partout), de nouveaux codes couleur, ou des modifications dans des parties que tu n'avais pas demandées.

Exercice 3 · libre

La page qui déborde sur téléphone

exercices/m1-03/deborde/ s'affiche bien sur ordinateur. Mais à 375 px, on peut faire défiler la page de gauche à droite. Il y a 3 causes. Trouve-les avec les outils, puis corrige le CSS.

Résultat attendu : à 375 px, aucun défilement horizontal. La page reste correcte sur ordinateur.

Pistes
  • Dans l'onglet Éléments, survole chaque bloc : le navigateur affiche sa largeur réelle.
  • Astuce de pro : ajoute temporairement * { outline: 1px solid red; } dans le CSS. Toutes les boîtes apparaissent, et celle qui dépasse se voit tout de suite.
  • Lis les commentaires dans le CSS : parfois l'IA explique très bien pourquoi elle a fait une erreur.
Correction
  1. .conteneur { width: 960px; } : la boîte fait 960 px, même sur un écran de 375 px. Remplacer par max-width: 960px;.
  2. L'image de la bannière fait 1200 px de large et rien ne la limite. Ajouter img { max-width: 100%; height: auto; }.
  3. h1 { white-space: nowrap; } interdit au titre de passer à la ligne. Sur un petit écran, il dépasse. Supprimer cette ligne : un titre qui passe sur deux lignes, c'est normal sur téléphone.

Corrige une cause à la fois et reteste : c'est comme ça que tu sais laquelle faisait quoi.

Teste-toi

1. Sur téléphone, la page s'affiche en tout petit, comme une version d'ordinateur rétrécie. Qu'est-ce qui manque probablement ?

Sans la balise viewport, le téléphone simule un écran d'environ 980 px et rétrécit tout. Les règles @media ne servent à rien tant que cette balise manque.

2. Dans le panneau Styles, une règle apparaît barrée. Qu'est-ce que ça veut dire, le plus souvent ?

C'est la cascade : la règle barrée a perdu face à une autre. Si un petit triangle jaune apparaît à côté, c'est différent : la propriété est mal écrite et le navigateur l'ignore.

3. L'IA a mis width: 1100px sur le conteneur principal. Quel est le problème ?

width impose une largeur exacte. max-width fixe une limite : la boîte peut rétrécir sur un petit écran, mais ne dépassera jamais 1100 px sur un grand.
