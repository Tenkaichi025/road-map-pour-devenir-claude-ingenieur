Leçon 1.5

Diagnostiquer avec les outils du navigateur

L'idée

Un bug, c'est un écart entre ce que tu attends et ce que tu vois. Le navigateur te donne des indices précis pour le réduire. La Console affiche les erreurs JavaScript, avec le fichier et la ligne. L'onglet Réseau montre les fichiers qui manquent. L'onglet Éléments montre la page réelle.

Diagnostiquer, ce n'est pas deviner. C'est observer, localiser, vérifier, puis corriger. Et quand tu passes le problème à l'IA, la qualité de ta description décide de la qualité de sa correction.

Exemple concret

Un tableau de bord météo affiche la température actuelle… et voici ce qu'on voit à l'écran :

undefined °C

Aucune erreur dans la Console. Le mot undefined veut dire : « tu demandes une valeur qui n'existe pas ». Voici la méthode en 4 étapes.

  1. Observer. Qu'est-ce qui s'affiche exactement, et où ? Ici : « undefined °C », dans le gros chiffre de la température.
  2. Localiser. Quelle ligne de code produit ce texte ? Cherche °C ou #temperature dans les fichiers (Ctrl + Maj + F dans VS Code).
  3. Vérifier. Affiche les données réelles. Tape dans la Console : METEO.maintenant, puis Entrée.
  4. Corriger, puis revérifier. Recharge la page, regarde la Console, et contrôle le reste de la page.
// donnees.js
const METEO = { maintenant: { temp: 29, humidite: 78 } };

// app.js
formater(m.temperature)    // la clé s'appelle « temp », pas « temperature »

La Console a répondu {temp: 29, humidite: 78}. Le code demande temperature. Cause trouvée.

Lire un message d'erreur

Uncaught TypeError: Cannot read properties of undefined (reading 'map')    app.js:31
  • TypeError : le type de problème (ici, une opération sur une valeur qui ne s'y prête pas).
  • Cannot read properties of undefined (reading 'map') : le code a écrit quelque_chose.map, mais quelque_chose vaut undefined.
  • app.js:31 : le fichier et la ligne. C'est un lien : clique dessus.

Les messages que tu verras le plus

  • X is not defined : un nom mal écrit, une variable jamais créée, ou un script qui n'a pas été chargé.
  • Cannot read properties of null : querySelector n'a rien trouvé. Le sélecteur est faux, ou le script s'exécute trop tôt.
  • Cannot read properties of undefined : les données n'ont pas la forme que le code attend.
  • 404 ou ERR_FILE_NOT_FOUND dans Réseau : un mauvais chemin de fichier.

Le rapport de bug pour l'IA

« Ça marche pas, corrige » oblige l'IA à deviner. Donne-lui plutôt ceci :

Ce que je fais : j'ouvre index.html dans Chrome.
Ce que j'attends : la température actuelle, « 29 °C ».
Ce que je vois : « undefined °C ». Aucune erreur dans la Console.
Fichiers concernés : app.js (affichage), donnees.js (données).
Ce que j'ai vérifié : METEO.maintenant vaut { temp: 29, humidite: 78, ... }.
Demande : explique la cause avant de corriger, puis corrige seulement ce bug.

Vérifier le travail de l'IA

L'IA te dit « c'est corrigé ». Avant de la croire :

  • Elle a expliqué la cause, pas seulement modifié du code.
  • Le symptôme exact a disparu : refais exactement les mêmes étapes qu'avant.
  • La Console est vide, et l'onglet Réseau n'a aucune ligne rouge.
  • Le reste de la page marche toujours : une correction peut casser autre chose à côté.
  • Elle n'a pas caché l'erreur au lieu de la corriger : un try/catch vide, un || 0 ajouté pour faire disparaître undefined, des ?. partout.
  • Si une correction fait apparaître un nouveau problème, recommence la méthode : un bug peut en cacher un autre.

À retenir

  1. Un bug = un écart entre ce qu'on attend et ce qu'on voit. Décris les deux précisément.
  2. Console pour les erreurs JavaScript (avec fichier et ligne), Réseau pour les fichiers, Éléments pour la page réelle.
  3. undefined = tu demandes une valeur qui n'existe pas. Vérifie le nom et la forme des données.
  4. Un bon rapport à l'IA : ce que je fais, ce que j'attends, ce que je vois, le message exact, les fichiers.
  5. Corriger, ce n'est pas cacher l'erreur. Exige la cause.

Exercice 1 · guidé

Lire une erreur jusqu'à la ligne fautive

  1. Ouvre la recette du garba. Clique sur « J'aime ». Le compteur ne bouge pas.
  2. F12, onglet Console. Clique encore sur « J'aime » : une erreur rouge apparaît.
  3. Lis le message mot à mot. Quelle opération a échoué ? Sur quelle valeur ?
  4. Clique sur le lien app.js:6 à droite du message. L'onglet Sources s'ouvre sur la ligne fautive.
  5. Compare le sélecteur utilisé dans le code avec les id du HTML (onglet Éléments).
  6. Corrige app.js dans ton éditeur, recharge, teste.

Résultat attendu : le compteur augmente à chaque clic, et la Console reste vide.

Indices

Le message est Cannot set properties of null (setting 'textContent'). Quelque chose vaut null : c'est le résultat d'un querySelector qui n'a rien trouvé.

Correction

Ligne 6, le code cherche #compteur, mais dans le HTML le nombre est dans <span id="nb-likes">. querySelector renvoie null, et on ne peut pas modifier le texte de « rien ». Correction : 

document.querySelector("#nb-likes").textContent = likes;

Remarque : l'erreur n'apparaît qu'au clic, pas au chargement. Certains bugs ne se montrent que quand tu fais l'action. C'est pour ça qu'il faut tester chaque bouton.

Exercice 2 · semi-guidé

Le « undefined » de la météo, avec Claude

  1. Ouvre le tableau de bord météo. Tu vois « undefined °C ».
  2. Tu verras aussi une erreur rouge dans la Console. Elle concerne un autre bug : garde-la pour l'exercice 3. Ici, on ne s'occupe que de la température.
  3. Applique les étapes « observer » et « localiser » sans IA. Tape METEO.maintenant dans la Console.
  4. Copie le dossier meteo dans un dossier de travail. Rédige un rapport de bug avec les 6 parties du modèle, puis donne-le à Claude dans cette copie.
  5. Vérifie sa réponse avec la liste « Vérifier le travail de l'IA ».

Résultat attendu : « 29 °C » s'affiche. Claude a expliqué la cause avant de corriger, et il n'a modifié qu'une seule ligne.

Indices

Le ressenti affiche bien « 33 °C ». Compare les deux lignes qui affichent la température et le ressenti dans app.js.

Correction

Cause : app.js, ligne 23, lit m.temperature, alors que la donnée s'appelle temp dans donnees.js. Correction en une ligne : 

document.querySelector("#temperature").textContent = formater(m.temp);

Corrections à refuser, même si « undefined » disparaît :

  • formater(m.temperature || 0) : affiche « 0 °C ». C'est faux, et c'est pire : plus personne ne verra le bug.
  • Renommer temp en temperature dans les données : ça marche ici, mais dans une vraie appli, les données viennent d'une API que tu ne contrôles pas.
Exercice 3 · libre

Les 3 bugs cachés de la météo

Après l'exercice 2, le tableau de bord a encore 3 problèmes. Trouve-les tous. Pour chacun, note le symptôme, la cause et l'endroit (fichier:ligne). Corrige-les seul ou avec Claude, mais avec un rapport de bug pour chacun.

Résultat attendu : les 5 jours de prévisions s'affichent avec leurs icônes. Le bouton °F affiche 84,2 °F pour 29 °C. La Console est vide et l'onglet Réseau n'a aucune ligne rouge.

Pistes
  • Un bug se voit dans la Console, un autre dans l'onglet Réseau.
  • Le troisième ne se voit dans aucun outil : seulement en comparant le résultat à une valeur connue. 0 °C = 32 °F, et 100 °C = 212 °F.
  • Un bug peut en cacher un autre : tant qu'il y a une erreur dans la Console, une partie du code ne s'exécute jamais.
Correction
  1. Console : Cannot read properties of undefined (reading 'map'), app.js ligne 31. Le code lit METEO.prevision, alors que les données s'appellent previsions. Conséquence cachée : le script s'arrête là, donc le bouton °F n'est jamais branché et ne réagit pas. Correction : METEO.previsions.map(...).
  2. Réseau : les icônes sont en rouge (img/nuageux.svg introuvable). Ligne 16, le chemin est img/, alors que le dossier s'appelle icones/. Correction : "icones/" + nom + ".svg".
  3. Aucun outil : une fois le bouton branché, 29 °C donne 75,2 °F au lieu de 84,2 °F. Ligne 4, la formule ajoute 23 au lieu de 32. Correction : (celsius * 9) / 5 + 32.

Le bug 3 est le plus dangereux, et c'est celui que l'IA produit le plus souvent : un code qui tourne sans erreur, mais qui calcule faux. Seule une valeur de contrôle connue le révèle. On reparlera de ces vérifications à la leçon 4.5, sur les tests.

Teste-toi

1. La Console affiche : Cannot read properties of null (reading 'addEventListener'). Quelle est la cause la plus probable ?

null est ce que querySelector renvoie quand il ne trouve rien. Vérifie l'orthographe du sélecteur, puis la présence de defer sur le script.

2. L'IA « corrige » un undefined °C en écrivant formater(m.temperature || 0). Est-ce une bonne correction ?

Faire disparaître un message n'est pas corriger. Ici, la page affiche maintenant une information fausse, et le vrai problème (un mauvais nom de donnée) est toujours présent.

3. Que doit contenir en priorité un rapport de bug pour l'IA ?

L'écart entre l'attendu et l'observé, plus le message exact, permettent de localiser le problème. Tout le projet noierait l'information. Mieux vaut indiquer les fichiers concernés.
