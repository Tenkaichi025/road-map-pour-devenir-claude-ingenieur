Leçon 1.1

Comment une page s'affiche

L'idée

Quand tu ouvres une page, ton navigateur fait trois choses : il demande des fichiers, il les lit, puis il dessine. Le fichier HTML arrive toujours en premier. En le lisant, le navigateur découvre qu'il a besoin d'autres fichiers : une feuille de style CSS, un script JavaScript, des images. Il va les chercher un par un.

Chaque langage a son rôle. Le HTML dit ce qu'il y a sur la page. Le CSS dit à quoi ça ressemble. Le JavaScript dit comment ça réagit.

Pourquoi c'est utile avec l'IA ? Quand elle te livre une page qui « ne marche pas », tu sauras poser les bonnes questions : est-ce que le fichier est arrivé ? Est-ce qu'il a été lu ? Est-ce qu'il a planté ?

Exemple concret

Une petite galerie photo d'Abidjan. Voici son fichier index.html. Regarde bien : les photos ne sont pas dedans. C'est le JavaScript qui les ajoutera. 

<!doctype html>
<html lang="fr">
  <head>
    <meta charset="utf-8">
    <title>Galerie d'Abidjan</title>
    <link rel="stylesheet" href="style.css">      <!-- 2. le CSS est demandé -->
    <script src="galerie.js" defer></script>      <!-- 3. le JS est demandé -->
  </head>
  <body>
    <h1>Galerie d'Abidjan</h1>
    <div id="photos"></div>                         <!-- vide : le JS le remplira -->
  </body>
</html>

Ce qui se passe, dans l'ordre

  1. Le navigateur demande index.html et le reçoit.
  2. Il le lit de haut en bas et construit le DOM : la liste organisée de tous les éléments de la page, rangés comme un arbre (tu le verras en détail à la leçon 1.4).
  3. Il tombe sur <link> : il demande style.css. Tant que le CSS n'est pas arrivé, il n'affiche rien. Sinon tu verrais la page clignoter sans style.
  4. Il tombe sur <script defer> : il demande galerie.js. Le mot defer lui dit : « télécharge-le maintenant, mais exécute-le seulement quand tout le HTML aura été lu ».
  5. Il applique le CSS aux éléments et dessine la page.
  6. Le JavaScript s'exécute et ajoute trois balises <img>. Le navigateur découvre alors les images, les demande, puis redessine la page.

Ici, la page est ouverte depuis ton disque : son adresse commence par file:// et les fichiers viennent de ton ordinateur. Sur un vrai site, l'adresse commence par https:// et les fichiers viennent d'un serveur. Le principe reste le même. Le module 2 te montre le côté serveur.

Vidéo

Vérifier le travail de l'IA

L'IA vient de te livrer une page. Avant de dire « c'est bon » :

  • Ouvre-la toi-même dans un vrai navigateur. Ne crois pas « ça marche » sur parole : l'IA ne voit pas ton écran.
  • Ouvre l'onglet Réseau (touche F12, puis recharge la page). Chaque fichier cité dans le HTML doit apparaître, et aucun ne doit être en rouge (erreur 404 ou ERR_FILE_NOT_FOUND).
  • Ouvre l'onglet Console : aucune erreur rouge au chargement.
  • Les chemins correspondent aux vrais noms de fichiers, majuscules comprises. Windows accepte Photo.jpg pour photo.jpg, mais GitHub Pages non : la page marchera chez toi et cassera en ligne.
  • Un script qui touche aux éléments de la page est chargé avec defer, ou placé tout en bas du <body>.
  • Chaque image a un attribut alt : le texte affiché si l'image ne charge pas.

À retenir

  1. Le navigateur demande d'abord le HTML, puis tous les fichiers que le HTML cite.
  2. HTML = le contenu. CSS = l'apparence. JavaScript = le comportement.
  3. Un fichier qui n'arrive pas casse une partie de la page sans prévenir. L'onglet Réseau te le montre.
  4. Les erreurs JavaScript s'affichent dans la Console. C'est le premier endroit où regarder.
  5. Ouvre, recharge, regarde Réseau et Console. Toujours.

Exercice 1 · guidé

Regarder une page se charger

  1. Ouvre exercices/m1-01/galerie/index.html dans ton navigateur.
  2. Appuie sur F12 (ou clic droit sur la page, puis Inspecter). Les outils de développement s'ouvrent.
  3. Clique sur l'onglet Réseau (en anglais : Network).
  4. Recharge la page avec Ctrl + R, en gardant les outils ouverts.
  5. Pour chaque ligne de la liste, note sur un papier : le nom du fichier, son type (colonne Type) et sa position dans l'ordre.
  6. Clique sur style.css dans la liste, puis sur l'onglet Réponse (Response) : tu vois exactement ce que le navigateur a reçu.

Résultat attendu : une liste de 6 fichiers. D'abord index.html, puis style.css et galerie.js, et enfin les 3 images. Tu sais expliquer pourquoi les images arrivent en dernier.

Indices

La liste est vide ? Les outils doivent être ouverts pendant le rechargement. Vérifie aussi que le filtre en haut de l'onglet est sur Tout (All).

Pour comprendre l'ordre, regarde la colonne Initiateur (Initiator) : elle dit qui a demandé chaque fichier.

Correction
  1. index.html (document) : c'est toi qui l'as demandé.
  2. style.css (stylesheet) : demandé par le HTML.
  3. galerie.js (script) : demandé par le HTML.
  4. plateau.svg, lagune.svg, marche.svg : demandés par galerie.js.

Les images arrivent en dernier parce qu'elles ne sont pas écrites dans le HTML. Le navigateur ne les découvre qu'au moment où le JavaScript les ajoute. La colonne Initiateur le confirme : elle indique galerie.js pour les trois images.

Exercice 2 · semi-guidé

Prédire, puis vérifier une page faite par Claude

  1. Crée un dossier vide ma-galerie où tu veux sur ton ordinateur.
  2. Ouvre Claude Code dans ce dossier (ou Claude sur le web) et envoie ce message :
Crée une petite galerie photo en 3 fichiers séparés : index.html,
style.css et galerie.js. Le JavaScript affiche 4 images à partir
d'un tableau. Utilise des images de https://picsum.photos.
N'utilise aucune bibliothèque.
  1. Avant d'ouvrir la page, lis le <head> de index.html et écris ta prédiction : quels fichiers seront demandés, et dans quel ordre ?
  2. Ouvre la page et compare ta prédiction avec l'onglet Réseau.
  3. Demande à Claude : « Explique-moi, ligne par ligne, la balise <head> de index.html. » Compare son explication avec ce que tu as observé.

Résultat attendu : ta prédiction correspond à l'onglet Réseau. Pour chaque fichier, tu sais dire qui l'a demandé : le HTML ou le JavaScript.

Indices

Plusieurs lignes pour une seule image ? C'est normal avec picsum.photos : l'adresse de départ renvoie vers une autre adresse (code 302), puis l'image arrive. Tu verras ce mécanisme au module 2.

La galerie reste vide ? Regarde la Console avant tout.

Correction

Ordre habituel : index.html, puis style.css et galerie.js, puis les 4 images (initiateur : galerie.js).

Si la galerie est vide et que la Console affiche Cannot read properties of null, alors Claude a placé le script dans le <head> sans defer. Le script s'exécute avant que la <div> existe, et il ne la trouve pas. La correction : ajouter defer. Si ça t'est arrivé, bravo : tu viens de trouver ton premier bug d'IA.

Exercice 3 · libre

Réparer la galerie cassée

Quelqu'un a modifié la galerie, et maintenant exercices/m1-01/galerie-cassee/ s'affiche sans style et sans photos. Il y a 3 problèmes. Trouve-les avec les onglets Réseau et Console uniquement, sans demander à l'IA, puis corrige les fichiers dans ton éditeur.

Résultat attendu : la page est identique à la galerie de l'exercice 1. L'onglet Réseau n'a aucune ligne rouge et la Console est vide.

Pistes
  • Compare le nom des fichiers demandés (onglet Réseau) avec les fichiers qui existent vraiment dans le dossier.
  • Une erreur dans la Console donne le fichier et le numéro de la ligne. Clique dessus.
  • Corrige un problème, recharge, et regarde à nouveau : un bug peut en cacher un autre.
Correction
  1. Pas de style : index.html demande css/style.css, mais le fichier est à la racine du dossier. Correction : href="style.css".
  2. Erreur dans la Console : Cannot read properties of null (reading 'append'). Dans galerie.js, le code cherche #photo, alors que la <div> s'appelle photos. Correction : querySelector("#photos").
  3. Images en rouge dans Réseau (visible seulement après la correction 2) : le code cherche les images dans photos/, alors que le dossier s'appelle images/. Correction : "images/" + photo.fichier.

Teste-toi

1. L'IA t'a livré une page : le texte s'affiche, mais sans aucune mise en forme. Que regardes-tu en premier ?

La mise en forme vient du CSS. Si elle manque complètement, le fichier CSS n'est probablement jamais arrivé : un mauvais chemin dans <link>. L'onglet Réseau te le montre en rouge.

2. Dans la galerie, pourquoi les images arrivent-elles après galerie.js ?

Le navigateur ne peut demander un fichier qu'après l'avoir découvert. Ici, les balises <img> n'existent qu'une fois galerie.js exécuté.

3. Que fait l'attribut defer sur une balise <script> ?

Avec defer, le script attend que tout le HTML ait été lu avant de s'exécuter. Il trouve donc les éléments qu'il cherche. Sans defer dans le <head>, il s'exécute trop tôt.
