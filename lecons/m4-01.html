Leçon 4.1

Git, ton filet de sécurité

L'idée

L'IA modifie vite, et beaucoup. Git est ta machine à remonter le temps : tant qu'un état du projet est commité, tu peux y revenir, quoi que l'IA fasse ensuite. Laisser l'IA travailler sans commit, c'est faire du trapèze sans filet.

Trois habitudes changent tout. Des commits atomiques : un commit = une intention, petit, avec un message qui dit ce qui a vraiment changé. On peut alors annuler une chose sans tout annuler. Une branche pour l'IA : elle travaille sur ia/…, et main ne reçoit que ce que tu as vérifié. Et un point de départ propre : avant de lancer l'IA, ton travail en cours est commité, ou mis de côté avec git stash.

Après le passage de l'IA, deux contrôles avant de fusionner : git diff main --stat (quels fichiers ont bougé, et est-ce justifié ?) et les tests. Si ça ne va pas, la branche part à la poubelle. Main, lui, n'a jamais été touché.

Exemple concret

Un petit projet Node.js qui calcule des devis et des frais de livraison à Abidjan, avec ses tests. Tu demandes à l'IA d'ajouter une remise fidélité de 10 %. Elle travaille sur la branche ia/remise-fidelite, et livre un seul commit : « Ajoute la remise fidélité et quelques améliorations ». Les tests sont tous verts : 

node --test
ℹ pass 6
ℹ fail 0

Tout va bien ? Regarde quels fichiers ont bougé par rapport à main :

git diff main --stat
 README.md               | 16 +++++++++++++---
 src/devis.js            |  8 +++++---
 src/livraison.js        |  6 +++---        ← tu n'as rien demandé sur la livraison
 src/remise.js           |  6 ++++++
 tests/livraison.test.js |  4 ++--          ← ni sur ses tests
 tests/remise.test.js    | 11 +++++++++++

Le détail de src/livraison.js et de son test :

git diff main -- src/livraison.js tests/livraison.test.js
-  return Math.ceil((base + supplement) / 100) * 100;
+  return Math.round((base + supplement) / 100) * 100;
-  assert.equal(fraisLivraison("Plateau", 7.2), 2000);
+  assert.equal(fraisLivraison("Plateau", 7.2), 1900);

L'IA a « simplifié » l'arrondi des frais de livraison (à la centaine la plus proche au lieu de la centaine supérieure). Puis, voyant le test échouer, elle a changé la valeur attendue du test. Chaque livraison lourde te rapporterait désormais 100 F de moins, et les tests restent verts. Seul le --stat l'a trahie.

Garder le bon, jeter le reste

La remise elle-même est bonne. On la récupère seule, sur une branche propre, en prenant uniquement les fichiers voulus dans la branche de l'IA : 

git switch main
git switch -c remise-propre
git restore --source ia/remise-fidelite -- src/remise.js tests/remise.test.js src/devis.js
node --test                                   # 6 tests verts, avec l'arrondi d'origine
git add -A
git commit -m "Ajoute la remise fidélité"     # un commit, une intention, 3 fichiers
git switch main
git merge remise-propre
git branch -D ia/remise-fidelite remise-propre

Les commandes du filet

CommandeÀ quoi elle sert
git statusVoir ce qui n'est pas commité. Doit être propre avant de lancer l'IA.
git stash push -m "…"Mettre ton travail en cours de côté. git stash pop le ramène.
git tag avant-iaPoser un repère sur l'état actuel, pour y revenir facilement.
git switch -c ia/…Créer la branche de travail de l'IA.
git diff main --statLa liste des fichiers modifiés par rapport à main.
git restore --source <branche> -- <fichiers>Prendre seulement certains fichiers d'une autre branche.
git reset --hard avant-iaRevenir exactement au repère. Efface tout ce qui a été fait depuis, commité ou non.
git revert <commit>Annuler un commit déjà poussé, en ajoutant un commit inverse. L'historique partagé reste intact.

git reset --hard est le bouton « tout effacer » : parfait sur une branche d'essai locale, dangereux partout ailleurs. Sur ce qui a déjà été poussé et partagé, on ne réécrit pas l'histoire : on utilise git revert.

Vérifier le travail de l'IA

Avant, pendant et après le passage de l'IA :

  • Avant de lancer l'IA : git status est propre (travail commité ou mis de côté), et tu es sur une branche ia/….
  • Refuse les commits « fourre-tout » (« quelques améliorations », « divers correctifs ») : un commit = une intention, avec un message qui dit ce qui a changé.
  • git diff main --stat : chaque fichier listé doit être justifié par ta demande. Un fichier inattendu, c'est une modification non demandée.
  • Un test dont la valeur attendue a changé, alors que ta demande ne le justifie pas : alerte rouge. L'IA a pu « réparer » le test au lieu du code (leçon 4.5).
  • Les tests passent sur la branche avant la fusion, et encore après.
  • L'IA ne lance aucune commande destructrice sans ton accord : git reset --hard, git push --force, git clean -fd, git checkout -- .. Dans Claude Code, garde la demande de permission pour ces commandes.
  • Rien de ce qui a été poussé et partagé n'est réécrit : git revert, jamais reset suivi d'un push --force sur main.
  • Aucun fichier en trop dans les commits : secrets, node_modules, bases de données, fichiers générés (git add -A prend tout).

À retenir

  1. Ce qui est commité est récupérable. Avant de lancer l'IA : un état propre et un repère (git tag).
  2. L'IA travaille sur une branche ia/…. Main ne reçoit que ce que tu as vérifié.
  3. Des commits atomiques : une intention par commit. Refuse les « fourre-tout ».
  4. git diff main --stat révèle les modifications non demandées, même quand les tests sont verts.
  5. reset --hard pour jeter un brouillon local, revert pour annuler ce qui est déjà partagé.

Exercice 1 · guidé

Démasquer le commit fourre-tout, et garder le bon

  1. Depuis exercices/m4-01 : node preparer-exercice.js C:\exos\devis-livraison. Puis va dans ce dossier.
  2. git status, puis git log --oneline --all, puis node --test.
  3. Essaie git switch ia/remise-fidelite. Git refuse : lis pourquoi. Mets ton travail de côté avec git stash push -m "mon travail en cours", puis change de branche.
  4. node --test, puis git diff main --stat. Quels fichiers n'ont rien à voir avec une remise ?
  5. Lis le détail : git diff main -- src/livraison.js tests/livraison.test.js.
  6. Récupère seulement la remise sur une branche propre, en suivant la section « Garder le bon, jeter le reste ».
  7. De retour sur main, après la fusion : git stash pop. Ton travail en cours est revenu ?

Résultat attendu : 6 tests verts sur la branche de l'IA, 3 fichiers non demandés repérés, un commit propre de 3 fichiers sur main, l'arrondi d'origine conservé (6 tests verts), et ton TODO revenu dans le README.

Indices

Le message de Git, au moment de changer de branche : « Your local changes to the following files would be overwritten ». Le README est modifié à la fois par toi et par la branche de l'IA.

Correction
  • git switch refuse, car ton README modifié serait écrasé. git stash le met de côté, sans rien perdre.
  • Sur la branche de l'IA : 6 tests verts. Mais --stat montre src/livraison.js, tests/livraison.test.js et README.md : rien de cela n'a été demandé.
  • Le diff : Math.ceil remplacé par Math.round, et l'attendu du test changé de 2000 en 1900 pour rester vert. 100 F perdus sur chaque colis concerné, sans aucune alerte.
  • Après git restore --source …, le commit « Ajoute la remise fidélité » ne contient que src/devis.js, src/remise.js et tests/remise.test.js. Les tests restent verts, avec l'attendu d'origine (2000).
  • git stash pop ramène la ligne « TODO : ajouter Grand-Bassam aux communes livrées ».
Exercice 2 · semi-guidé

Faire travailler Claude sur une branche, et décider

  1. Dans le dépôt d'entraînement, sur main, avec un git status propre : git tag avant-ia, puis git switch -c ia/livraison-express.
  2. Ouvre Claude Code dans ce dossier et demande :
Ajoute une option « livraison express » : les frais de livraison
sont majorés de 50 %, puis arrondis à la centaine supérieure.
Ne modifie que src/livraison.js et tests/livraison.test.js.
Ajoute au moins deux tests. Fais un commit pour le code et un
commit pour les tests, avec des messages précis.
  1. Contrôle : git log --oneline main.., git diff main --stat, git diff main, node --test.
  2. Décide. Si tout est conforme : git switch main, puis git merge ia/livraison-express. Sinon : git reset --hard avant-ia sur la branche, et recommence avec une demande plus précise.

Résultat attendu : deux commits aux messages précis, seulement les deux fichiers autorisés, les anciens tests inchangés et verts, au moins deux nouveaux tests, et une décision argumentée (fusion ou retour au repère).

Indices

Pour vérifier que les anciens tests n'ont pas été modifiés : dans git diff main -- tests/livraison.test.js, il ne doit y avoir que des lignes ajoutées (+), aucune ligne retirée (-).

Correction

Points à contrôler, et réactions possibles :

  • Un seul commit au lieu de deux : demande de le découper (ou accepte, si le diff est petit et propre : la règle sert la relecture, pas l'inverse).
  • Un fichier hors liste dans --stat : refuse, et répète la contrainte.
  • Un ancien test modifié : refuse sans discuter. La demande ne justifie aucun changement des tests existants.
  • Vérifie un calcul toi-même : Plateau, 2 kg, en express → 1500 × 1,5 = 2250 → 2300 après l'arrondi à la centaine supérieure. Un test qui attend 2250 serait faux.

git reset --hard avant-ia n'efface que la branche d'essai : main n'a jamais bougé.

Exercice 3 · libre

Le contrat Git de ton projet

Dans un de tes projets, écris une section « Git » dans son CLAUDE.md : branche ia/… obligatoire, un commit par étape, messages précis, fichiers autorisés, tests existants intouchables sans accord, aucune commande destructrice ni push sans ta permission. Puis applique ce contrat à ta prochaine vraie fonctionnalité, de la branche jusqu'à la fusion.

Résultat attendu : une section « Git » dans ton CLAUDE.md, et l'historique (git log --oneline --graph) d'une vraie fonctionnalité menée selon ce contrat.

Pistes
  • Le CLAUDE.md est lu par Claude Code à chaque session : c'est là que tes règles de travail ont le plus d'effet (on y revient en 4.2).
  • Dans les réglages de Claude Code, tu peux exiger une confirmation pour certaines commandes, comme git push.
  • Prends l'habitude de lire git diff --stat avant chaque fusion, même pour une petite modification.

Teste-toi

1. Tu as demandé une remise, les tests sont verts. Quelle commande te montre, en une ligne par fichier, tout ce que l'IA a modifié ?

git status ne montre que ce qui n'est pas commité, et les tests ne disent rien des fichiers touchés. git diff main --stat liste chaque fichier modifié par rapport à main, avec le nombre de lignes changées.

2. Tu as du travail non commité, et Git refuse de passer sur la branche de l'IA. Que fais-tu ?

git stash met ton travail de côté sans rien perdre. git reset --hard l'effacerait définitivement : ce qui n'a jamais été commité ne se récupère pas.

3. Un mauvais commit de l'IA a déjà été poussé sur GitHub, et ton collègue a récupéré le dépôt. Comment l'annuler ?

Réécrire un historique partagé casse le dépôt de tous ceux qui l'ont récupéré. git revert ajoute simplement un commit inverse : tout le monde peut le récupérer normalement.
